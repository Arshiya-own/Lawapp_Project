## 1. Purpose

This document defines the architecture, components, boundaries, and deployment model for Mini-JuriNex. All structural decisions described here are binding. Implementation details within a component are at the engineer's discretion unless otherwise specified in the backend, frontend, or AI/ML specs.

---

## 2. System Overview

Mini-JuriNex is a web application that helps lawyers find relevant precedents. The system is composed of:

- A **React frontend** served as static assets
- A **FastAPI backend** exposing a JSON REST API
- **Google OAuth 2.0** for authentication
- **Google Cloud Storage** for raw PDF storage
- A **vector store** for judgment chunk embeddings
- **Google Gemini API** for metadata extraction, dimensional query generation, and embeddings
- An **OCR service** for extracting text from uploaded scanned PDFs

## 4. Components

### 4.1 Frontend

- **Framework:** React 18 + TypeScript
- **Build:** Vite
- **Styling:** Tailwind CSS
- **State:** React Query for server state, React Context for auth state
- **Routing:** React Router v6
- **Deployment target:** Cloud Run or Firebase Hosting

Details in `02_frontend_spec.md`.

### 4.2 Backend

- **Framework:** FastAPI (Python 3.11)
- **ASGI server:** uvicorn
- **Deployment target:** Cloud Run

Details in `03_backend_spec.md`.

### 4.3 Authentication

- **Provider:** Google OAuth 2.0
- **Flow:** Authorization Code Flow with PKCE
- **Scopes required:** `openid`, `email`, `profile` — nothing more
- **Session mechanism:** HTTP-only secure cookies, or Authorization Bearer JWT signed by the backend. Either is acceptable. If using JWT, expiry is 60 minutes.

### 4.4 Storage

- **Raw PDF storage:** Google Cloud Storage bucket `jurinex-{env}-cases/`
- **Object key format:** `users/{user_id}/cases/{case_id}/original.pdf`
- **Access control:** private bucket, signed URLs only (15-minute expiry)

### 4.5 Vector Store

Acceptable options:
- **Vertex AI Vector Search** (preferred for production fidelity)
- **ChromaDB** (self-hosted on Cloud Run, acceptable for this exercise)
- **pgvector on Cloud SQL** (acceptable)
- **FAISS** in-memory (acceptable only if indexing happens at container start)

Choose one. Document your choice in `DEVIATIONS.md` only if you use something not on this list.

### 4.6 Gemini Integration

- **Text embeddings:** `text-embedding-004` — 768 dimensions
- **Generation tasks:** `gemini-2.5-flash` for metadata extraction and dimension generation
- Use the official `google-generativeai` Python SDK
- API key from Secret Manager (local dev: `.env`)

### 4.7 OCR

Acceptable options:
- **Google Document AI** (preferred for real scanned PDFs)
- **pytesseract** (acceptable — free, works on the sample PDFs)

Choose one. Specify in README.

## 5. Data Flow — Upload Pipeline

```
User uploads PDF
   │
   ▼
Backend receives multipart upload → validates size & MIME type
   │
   ▼
Backend streams to Cloud Storage at users/{user_id}/cases/{case_id}/original.pdf
   │
   ▼
Backend triggers OCR pipeline
   │
   ▼
Extracted text → Gemini metadata extractor → parsed metadata JSON
   │
   ▼
Metadata persisted (in-memory dict or Firestore — implementer's choice)
   │
   ▼
Response returned to frontend
```

## 6. Data & Time Conventions

**All timestamps in API responses MUST be UTC ISO 8601 with `Z` suffix.**
Example: `2026-04-19T14:30:00Z`
Not acceptable: `2026-04-19T14:30:00+00:00`, `2026-04-19T14:30:00.000Z` (no milliseconds).

All IDs generated by the system use UUIDv4. See `03_backend_spec.md` for per-entity ID prefix rules.

All JSON is encoded as UTF-8. All response bodies are JSON with `Content-Type: application/json`.

Byte sizes are reported as integers in bytes, not strings.

Currency, if it were present in this system, would be in minor units (paise) — not applicable here, but noted for future consistency.

## 7. Data Flow — Query Pipeline

```
User (on Results page) triggers "Find Precedents"
   │
   ▼
Frontend calls POST /cases/{case_id}/dimensions
   │
   ▼
Backend loads case metadata → calls Gemini dimension generator → returns 3 queries
   │
   ▼
Frontend calls POST /cases/{case_id}/retrieve
   │
   ▼
Backend:
  For each of the 3 dimensions:
     - Embed query via text-embedding-004
     - Vector similarity search against indexed corpus
     - Filter by similarity threshold
     - Rerank by court hierarchy (see 04_ai_ml_spec.md)
     - Take top 5
  Aggregate results → return to frontend
```

Retrieval details in `04_ai_ml_spec.md`.

## 8. Corpus Indexing (One-Time Script)

At container start or via a dedicated admin endpoint, the backend:

1. Loads `judgments_corpus.json`
2. For each judgment, chunks per the rules in `04_ai_ml_spec.md`
3. Embeds each chunk via `text-embedding-004`
4. Stores `{chunk_id, judgment_id, text, embedding, metadata}` in the vector store

Indexing is **not** a user-facing endpoint. It runs once per deployment.

## 9. Deployment

### 9.1 Backend

- Docker image built from `backend/Dockerfile`
- Deployed to Cloud Run with minimum instances = 0, maximum instances = 2
- Memory: 1 GiB
- CPU: 1 vCPU
- Request timeout: 60 seconds
- Environment variables from Secret Manager (production) or `.env` (local)

### 9.2 Frontend

- Static assets built via `vite build`
- Deployed to Cloud Run (nginx container) or Firebase Hosting
- Frontend env var `VITE_API_BASE_URL` points to the backend URL

### 9.3 Required Secrets

| Secret | Purpose |
|---|---|
| `GOOGLE_OAUTH_CLIENT_ID` | OAuth client identifier |
| `GOOGLE_OAUTH_CLIENT_SECRET` | OAuth client secret |
| `GEMINI_API_KEY` | Gemini API access |
| `JWT_SIGNING_SECRET` | If using JWT session model |
| `GCP_PROJECT_ID` | For GCS + Vertex access |
| `GCS_BUCKET_NAME` | Case storage |

All must be loaded via environment variables. Committing any of these to the repo is a disqualifier.

## 10. Observability

Minimum logging requirements:
- Every API request logs: `method, path, status_code, latency_ms, user_id (if auth), request_id`
- Every Gemini call logs: `model, token_count_estimate, latency_ms`
- OCR calls log: `duration_ms, pages_processed`

Use `structlog` or Python `logging` with JSON formatter. Logs appear in Cloud Run's log stream — do not ship to external services.

---

## 11. Security

- **CORS:** Frontend origin only. No wildcard.
- **CSRF:** SameSite=Strict cookies if using cookie sessions.
- **File upload limits:** Max 20 MB, MIME type must be `application/pdf`.
- **Authentication check:** All `/cases/*` endpoints require authenticated user. Unauthenticated → 401.
- **Authorization:** A user can only access their own cases. Accessing another user's case → 404 (not 403 — avoid leaking existence).

---

## 12. Out of Scope (Do Not Build)

- User profile editing
- Case sharing between users
- Billing or quota enforcement
- Real-time collaboration
- Email notifications
- Admin dashboard
- Anything not explicitly in the frontend, backend, or AI/ML specs
